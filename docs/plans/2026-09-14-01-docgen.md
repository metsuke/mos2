## Objetivo

Regenerar todos los documentos del clone (raíz, docs/, specs/, man/) por código: plantilla + scan del repo + almacén CRUD. La IA no reescribe folios; propone altas/bajas atómicas sobre JSON y `docgen generate`.

Cierre de campaña de producto: motor, comando, REQ/áreas, HTML. El tag 0.2.8 sigue siendo decisión humana.

## Fuera de alcance

- Que la IA escriba el markdown final como vía habitual
- P2P / tienda / DepManager
- Regenerar código Python
- Borrar los .md actuales antes de ingestión
- Bump de Poetry en el primer commit

## Decisiones

1. El markdown generado pisa el documento actual.
2. Un documento por fase al construir el motor; el inventario queda cubierto por generate all.
3. Cada generate guarda la versión inmediatamente anterior en docs/docgen/backup/.
4. Fase 0 de cada documento: absorber el md de hoy a json (ingest excepcional).
5. Un JSON por spec (y análogo por documento no-spec).
6. Un JSON por requisito en docs/docgen/reqs/.
7. Áreas en areas.json, editables con `docgen area`.
8. Comando: docgen.
9. Tras generate: HTML en docs/docgen/html/<id>.html.
10. generate no vuelve a ingerir. ingest solo primera vez o recuperación.
11. Al ingest de REQ, un área desconocida se incorpora a areas.json. En CRUD a mano, el área debe existir o se crea con `docgen area add`.
12. El SRS se pinta con **una tabla por área**, no una tabla única.
