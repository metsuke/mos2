# Plan 2026-09-14-01 · docgen

**Fecha:** 2026-09-14  
**NN del día:** 01  
**Estado:** En curso

**Producto al cierre:** comando docgen usable; bump/tag según VERSIONING al final, no en el primer commit

---

## Objetivo

Regenerar todos los documentos del clone (raíz, docs/, specs/, man/) por código: plantilla + scan del repo + almacén CRUD. La IA no reescribe folios; propone altas/bajas atómicas.

Cierre de campaña solo cuando **todos** esos documentos funcionan con el método nuevo.

## Fuera de alcance

- Que la IA escriba el markdown final
- P2P / tienda / DepManager
- Regenerar código Python
- Borrar los .md actuales antes de ingestión

## Decisiones

1. El markdown generado pisa el documento actual.
2. Un documento por fase, con prueba, hasta cubrir el inventario completo.
3. Cada generate guarda la versión inmediatamente anterior en docs/docgen/backup/.
4. Fase 0 de cada documento: absorber el md de hoy a json + plantilla.
5. Un JSON por spec (y análogo por documento no-spec) + un JSON de áreas REQ.
6. Comando: docgen.

---

## Modelo

hoy.md --ingesta--> plantilla + json
código --scan-----> tablas (comandos, core, versión, man)
json   --CRUD-----> req / bloques / áreas
              \--> backup + pisa hoy.md

## Comando

docgen / docgen <id> / docgen all / docgen diff <id>
docgen ingest <id> / docgen backup-list <id>
docgen req list|add|set|rm
docgen area list|add
docgen bloque list|set <id> <clave>

## Fases

F0 cimientos: motor, comando, tests humo, areas.json, backup/.gitignore
F1 piloto man (echo o clear)
F2 tabla de comandos en un spec
F3 SRS + CRUD req
F4 resto uno a uno hasta inventario completo:
man restantes, USER_MANUAL, specs 00-10, CHANGELOG, README, AGENTS,
onboarding, A11Y, METHODOLOGY, VERSIONING, ENVIRONMENTS, STYLE_GUIDE,
INCENTIVOS, INTERACTION_REVIEW, DEUDA, plans/README, LICENSE si se documenta.

Regla: si el render es más corto que el backup y no hubo ingest completo, abortar y no pisar.
