Qué es MetsuOS (férreo)

  • SO simulado modular en Python; shell MOSh.
  • Núcleo moslib/; rootfs/ simulado.
  • Contrato: execute(args) y help() -> str no vacío.
  • Imports de comandos: solo stdlib + moslib (AST).
  • Usuario anfitrión; comandos user_*.py; nunca pisan sistema.
  • Tests de arranque bloqueantes.
  • A11Y de interfaz mandatoria.
  • Poetry + mos2.sh / install.sh multi-entorno.
  • Git, no APIs de un forge.
  • Comandos de calidad actuales: test, update, synccheck, docgen.
  • Tope 120 líneas por fichero de código; test 120 consulta sin tumbar el sistema.
  • Incentivos: vectores comunes; humanos se inclinan; IA está obligada. Sin karma.

Documentación y docgen

Fuente de verdad: JSON en docs/docgen/ (man/, specs/, pages/, root/, areas.json, index.json). El markdown publicado se pinta con docgen generate. Flujo normal de la IA: un JSON por mensaje, fichero entero, luego docgen generate <id> en el mismo lote. Si el id no está en el índice: docgen index add <id> <rel> en ese lote. docgen ingest solo primera absorción o recuperación desde markdown/backup. generate no ingerir: si ingerir al generar, el JSON se pisa con un md viejo o corto. Prohibido reescribir specs/manual/man enteros en el chat como vía habitual.

Edición: multi y write.sh

Dentro de MOS: m o multi. Se pega el bloque entero. multi acumula; no parsea hasta una línea que sea solo :e (ejecuta) o :q (cancela). ;e y ;q valen igual. Fuera de MOS: ./write.sh lanza el mismo multi. No emular el lote en bash. Forma del lote: write <ruta> <sha256 del fichero en claro> [prefijo]payload . docgen index add <id> <rel> docgen generate <id> Luego línea sola :e. Máximo tres writes por lote si son ficheros pequeños. write registra integridad si el hash coincide.

Codecs del payload

El hash es siempre SHA-256 del contenido en claro, no del payload. sin prefijo = Base64 del fichero gz: gzip+Base64 xz: lzma+Base64 b85: ascii85 gzb85: gzip+ascii85 xzb85: lzma+ascii85 La IA elige el más corto que el decoder ya tenga. Si CRC o payload inválido: el pegado se cortó; repetir en Base64 plano o pegar el fichero con code y ./arreglar_integridad.sh.

Cómo entregar trabajo al humano

  • Un paso / un fichero por mensaje, salvo pareja inseparable avisada (write + generate cuenta como un lote).
  • Fichero entero. Prohibido “añade esta fila”: las tablas van montadas.
  • Prohibido “usa lo que te di antes”: volver a pegar el documento.
  • Cachos solo si no cabe: cacho 1 sustituye todo; no dejar un spec inválido a mitad.
  • Completo habitual: lote write (hash + payload + punto) + generate, vía multi o ./write.sh.
  • Alternativa editor: mkdir / touch / code, luego el texto; después integridad.
  • Parcial (avisando “no sustituyas el fichero”): primero el recorte, luego code.
  • Encabezados sin numeración.
  • Directorios en tablas (una columna por nivel).
  • Comandos: Tipo A–Z, comando A–Z dentro del tipo.
  • Si el nuevo texto es más corto que el del repo: avisar. No resumir sin consultar.
  • Breadcrumb: campaña, grupo, bloque x/y, paso, %, contexto.
  • Si se salta un número de paso: explicar por qué en el mismo mensaje.
  • No usar «corrida». CHANGELOG: no dejar «Sin publicar» al humano.
  • Psicología: acompañar; prohibido dañar, desestabilizar o engañar.
  • Asimov (docs/INCENTIVOS.md): cita + nota de aplicación; no autocommit; no apagar tests.

Estado real del repositorio

1. Pedir synccheck cuando haya duda. 2. Leer por SHA (git show origin/main:archivo o raw con SHA). 3. No diagnosticar solo con .../main/ en CDN. 4. Si Poetry, README, CHANGELOG y comandos no cuadran: hotfix antes del siguiente bloque.

Integridad de emergencia

./arreglar_integridad.sh solo si MOS no arranca por hashes. Aviso 30 s con barra. Reescribe el manifiesto al contenido actual del clone y lanza ./mos2.sh con MOS_INTEGRIDAD=recargar. El alias mos2 no existe dentro de un script no interactivo. No es uso diario. No usarlo si no se reconocen los cambios.
